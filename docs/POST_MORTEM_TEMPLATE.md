# Template de Post-Mortem (Análise de Incidente)

**ID do Incidente:** #INC-YYYYMMDD-X
**Data:** YYYY-MM-DD
**Autor:** [Nome]
**Status:** [Em análise / Concluído]

## 1. Resumo Executivo
Uma breve descrição do que aconteceu, quem foi afetado e qual foi a gravidade.

## 2. Cronologia
- **HH:MM**: Início do incidente (detecção automática ou relato).
- **HH:MM**: Equipe notificada.
- **HH:MM**: Causa raiz identificada.
- **HH:MM**: Workaround aplicado (se houver).
- **HH:MM**: Correção definitiva (Hotfix) aplicada.
- **HH:MM**: Sistema normalizado.

## 3. Causa Raiz (Root Cause)
Explicação técnica detalhada de por que o incidente ocorreu (os "5 porquês").

## 4. Impacto
- **Usuários**: Quantos usuários foram afetados?
- **Dados**: Houve perda ou corrupção de dados?
- **Performance**: Houve lentidão perceptível?

## 5. Resolução
Como o problema foi resolvido a curto prazo.

## 6. Lições Aprendidas e Próximos Passos (Action Items)
O que faremos para evitar que isso aconteça novamente?
- [ ] Item 1 (Responsável: [Nome], Prazo: [Data])
- [ ] Item 2 (Responsável: [Nome], Prazo: [Data])

## 7. Apêndices
Logs, screenshots, links para métricas do Grafana/Sentry.
